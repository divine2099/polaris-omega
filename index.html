Polaris Omega

A cross-chain arbitrage engine with a solver-grade execution layer.

It finds price differences between decentralised exchanges, on one chain and between chains, and checks every trade exactly against the chain before sending it.

Its edge is between chains. There the winner is whoever prices both sides correctly and has inventory in place, not whoever is first into the block.

It moves money only through each exchange's own entry functions, never by sending it somewhere and hoping.

Built by Jamike Divine, a solo builder working with an AI system. Proven on a public test network; not yet traded with real money.

#01

What it is

The same asset is often priced slightly differently in two places at the same moment. Polaris Omega has two engines for that.

The first engine works inside one chain. It buys on one exchange and sells on another in a single transaction that either completes or does nothing, with the money borrowed and repaid inside that same transaction. It needs no capital of its own. But on one chain it is a race: whoever lands first in the block takes the trade, and hardware and position decide that race. This engine is the entry point and the steady base, not the edge.

The second engine works between chains, and that is where the edge sits. No loan can span two chains, so it needs real capital resting on each side. In exchange, it does not need to be first. The gaps it hunts last seconds to minutes rather than one block, so it competes on pricing both chains correctly, checking every leg exactly and moving inventory cheaply. Few players can do that, because it takes capital, risk control and infrastructure on several chains at once.

The solver layer is what makes the second engine work. A solver fills other people's orders on intent-based venues and moves assets between chains for a fee. Polaris Omega already speaks those venues' order formats natively, and its cross-chain engine uses them to move its own inventory. With enough inventory it can fill other people's cross-chain orders from the same capital, so moving its own money earns fees instead of costing them. That is why it is designed as a hybrid of arbitrageur and solver. The solver side is built and switched off today, because it needs that capital to front each fill.

#02

How it is built

Full architecture →

Inside the node

Most bots ask a node for data over the network and are always a little behind. On Ethereum, Base and Optimism this runs as an extension inside the node software itself. On Arbitrum and BNB Chain, whose nodes have no extension slot, it runs beside the node on the same machine and reads its live feed.

Every trade simulated exactly

Before anything is sent, the trade is run against the chain's current state on the same virtual machine the chain uses. If the result is off by the smallest unit, it is not sent.

One small contract, money through doors

A single contract with no stored state carries out each trade. Value moves only through an exchange's own entry functions, enforced when the trade is built rather than reviewed afterwards.

Two keys and a scoped vault

A single-transaction trade takes one key. Anything that settles in two parts needs a second, independent signer with its own rules. Inventory sits in a Safe, and the trading key gets only a narrow role over it.

Every claim names its check

A ledger records every assumption the system rests on, marked verified, unverified or falsified, with the test that decides it. The tools are built to tell "nothing was there" apart from "I could not look", because most tools print the same silence for both.

Found, simulated, signed and landed arbitrage trades on Base's public test network. Each landed trade was profitable after gas, and every receipt field was checked against the chain. Reverted attempts are counted too, because a revert still costs gas.

A Safe with a tightly scoped role traded part of its inventory exactly as simulated. Every attempt to step outside the role was refused by the role itself.

2026-11
The two-key path, end to end Stopped by its own check

Both signers up, a trade planned and simulated as its two transactions, and handed to the sender. The staleness check stopped it because the machine had fallen too far behind the chain, and nothing was signed. That is the right outcome, and it names the next step.

Not yet: no trade on a real network with real money, and no live record of returns.
#04

What holds it back

None of it is code
Critical
The machine

The development machine cannot host a node, so it reads the chain over the network. On Base, with a block every fifth of a second, that leaves it ~200 blocks behind against a 10-block window. The check is doing its job and has no setting to loosen. The fix is a bare-metal machine beside a node: about $456/month for one chain, ~$1,600/month for all five.

Critical
Capital

The single-chain engine needs only gas, and that is not where the edge is. The cross-chain engine, the solver fills and later market making all need working capital on each chain, to hold inventory and to front fills. That part is built, plans real candidates from live data, and stops at exactly this point.

High
Chain access

A paid plan at a hobby tier: enough to test, but a live run would spend more in a day than it allows. A private endpoint removes this.

High
The AI bill

One person builds this with an AI coding system, and its plan tier sets the pace. A better plan is the cheapest way to make everything move faster.

Roadmap

No dates until the machine exists
  1. A node machine for one chain. The system moves beside a node and stops falling behind.
  2. The first real-network trades, single-chain first, with small balances declared in advance and every transaction published net of gas.
  3. The cross-chain engine with working capital, starting with inventory on two chains in a vault the system cannot empty, every leg co-signed by two keys.
  4. The solver side, filling other people's cross-chain orders from that same inventory, starting with the venue that needs no one's permission.
  5. The other chains, one at a time, each with its own record.
